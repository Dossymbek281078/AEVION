Собрано из сессии `aevion-fan-pricing` (ветка `feat/fan-discounts`). **Ничего из
перечисленного я не правил** — зоны чужие. Здесь только то, что проверено

Порядок — по последствию, а не по объёму правки.

## 1. 🔴 Один холодный запрос к базе навсегда уводит модуль в in-memory

**Зона:** общая инфраструктура (`src/lib/ensure*Tables.ts` + `conceptBoardStore`,
`ecosystemStore`, `chatHistory`, `ecosystemEvents`).
**Масштаб:** 21 файл из 23.
**Последствие:** потеря данных.

```ts
if (ensured) return;
try { await pool.query("SELECT 1"); }
catch (e) {
  ensured = true;          // ← защёлка ВНУТРИ catch
  console.warn("[X] Database unavailable — falling back to in-memory store");
  return;
}
```

После **одного** неудачного `SELECT 1` модуль до конца жизни процесса пишет в
память — даже если база поднялась через секунду. Повторной попытки нет.

**Почему это не теория:** отказ ПЕРВОГО запроса на непрогретом пуле — измеренный
факт. Ровно из-за него в `lib/appSubscriptions` пришлось добавить вторую попытку:
покупатель, открывший страницу сразу после редеплоя, получал `appsSource:
"unavailable"` и пустой веер при купленных модулях. Значит на каждом редеплое
есть шанс, что модуль, к которому обратились первым, останется без базы, а в
логах будет одна строка `warn`.

**Починка — кулдаун вместо защёлки** (уже применена в `lib/discountIntegrityLog`
и `lib/appSubscriptions`, можно копировать):

```ts
let ensured = false;
let lastFailureAt = 0;
const ENSURE_RETRY_MS = 60_000;

if (ensured) return;
if (lastFailureAt && Date.now() - lastFailureAt < ENSURE_RETRY_MS) return;
// в catch:  lastFailureAt = Date.now();   // ensured НЕ трогаем
// после успеха:  ensured = true; lastFailureAt = 0;
```

**Требование к тесту — три половины:** сбой не роняет → в кулдаун повторов нет →
после кулдауна попытка повторяется и база подхватывается. Без третьей проверка
совместима с «навсегда in-memory», то есть с самим дефектом.

## 2. 🔴 OG-картинка подарка падает по ссылке, которую пересылают

**Зона:** банк (`frontend/src/app/bank/`).
**Файлы:** `gift/[id]/opengraph-image.tsx:63`, `share/[handle]/opengraph-image.tsx`.
**Последствие:** отказ рендера по внешнему вводу.

Три отдельные ошибки, все воспроизведены прогоном:

| Вход | Что происходит |
|---|---|
| `?p=` с `themeId:"constructor"` | `"constructor" in THEME_GRADIENT` = `true` → фолбэк на `"general"` НЕ срабатывает → функция уходит React-ребёнком → **исключение** |
| `?name=a&name=b` | Next отдаёт **массив**; `.slice` у массива работает, результат правдивый, фолбэк не срабатывает → `s.replace is not a function` |
| `?tier=constructor` | `TIER_COLOR[tier] ?? "#cbd5e1"` — `??` не ловит функцию, она уходит в CSS как цвет |

Тип в сигнатуре (`searchParams?: { name?: string }`) здесь не защищает: он
описывает намерение, а не то, что приходит из сети.

**Починка:** нормализатор на входе —
`const one = (v) => Array.isArray(v) ? v[0] : typeof v === "string" ? v : ""` —
плюс `Object.prototype.hasOwnProperty.call` вместо `in` и голого доступа. В
`gift` заодно валидировать `tryDecode` целиком: `amount` уходит в `.toFixed()`
без проверки типа.

## 3. 🟠 Прототипные ключи из тела запроса в QMelanin

**Зона:** QMelanin/QRenew (`src/routes/qmelanin.ts:254, 359`).
**Последствие:** HTTP 200 с мусором.

```ts
deficientKeys = b.deficientKeys.filter((k: string): k is BiomarkerKey => k in BIOMARKER_BY_KEY);
```

`BIOMARKER_BY_KEY` построен через `Object.fromEntries`, поэтому `"constructor"`,
`"__proto__"`, `"toString"` проходят фильтр. Ключи приходят из **тела запроса**.
Не падает: `.label` у функции просто `undefined` — клиент получает 200 с пустыми
карточками `{}` и `null` в списке продуктов (проверено прогоном).

**Починка:** `Object.prototype.hasOwnProperty.call(BIOMARKER_BY_KEY, k)`.
Тест: пять прототипных ключей дают пустой результат **и** реальный ключ
(`"copper"`) по-прежнему работает — без второй половины проверка ничего не значит.

## 4. 🟡 `Math.max(parseInt(...), 1)` даёт NaN — 8 мест

**Зоны:** метрики/инфра (`routes/events.ts` 181, 182, 322, 366), shadownet
(419, 467), deepsan (95), QReal (`qreal.ts:804`).
**Последствие:** пустой список вместо данных.

Выражение читается как «фолбэк плюс пол», но `?? "100"` ловит только
`undefined`, а `Math.max(NaN, 1)` — это `NaN`, и `.slice(0, NaN)` возвращает
**пустой массив**. У меня это показывало админу пустой список лидов вместо ста
записей (починено в `routes/pricing.ts`, `parseLimit()` — образец с тестом).

**Большинство мест в репозитории БЕЗОПАСНЫ** — там после `parseInt` стоит `|| 50`,
и `NaN` как falsy ловится (`conceptBoardStore`, `bureau` ×2, `devhub` ×3,
`build/messaging`, `build/stats`, `events:254`). Их трогать не надо.

**Отдельно `qreal.ts:804`** — разбор HTTP-заголовка `Range` при отдаче видео:
`Range: bytes=0-abc` даёт `end = NaN`, который уходит в поток. Единственное место
класса, где вход — заголовок, а не query; последствие стоит проверить отдельно.

## Что проверено и дефектом НЕ является

Чтобы никто не тратил на это время повторно:

- **`/api/qcontract/health` → 503 локально.** Ручка делает запрос к базе и честно
  отдаёт 503 с текстом ошибки. Локально Postgres не настроен — поведение верное.
  Это же объясняет часть из 19 красных смоуков (`qgood`, `qfusionai`, `ztide`,
  `qchaingov`): им нужна база, а не починка.
- **Крах `0xC0000409` в смоуках.** `all-smokes` обрабатывает его согласованно:
  игнорирует ровно тогда, когда смоук сам отчитался о нуле падений. У `qcontract`
  было настоящее «6 passed, 1 failed» — набор прав.
- **Права доступа Universe.** Сначала я заявил «`pro` получает 0 модулей из 43» —
  **неверно**: зонд подавал в `isModuleEntitled` сырой `tier:"pro"` в обход
  `normalizeTier`, которая мапит его в `full`. Реальный путь всегда нормализует,
  права полные.
- **Фронтенд системной защёлки НЕ имеет.** Прогрепан тем же правилом: всего пять
  модульных булевых флагов. `sentry.inited` и `AutoTranslate.i18nWarned` —
  намеренные (init-once и warn-once); `Globus3D.countriesCacheBuildStarted` и
  `borderVerticesBuildStarted` работают над СТАТИЧЕСКИ импортированными данными,
  сети там нет — повтор детерминированного вычисления ничего бы не дал.
  Настоящих ловушек на фронте было две, обе в кэшах промисов, обе починены
  (`ModulePricingChip`, `FanDiscountPanel`).
- **`lib/sentry.ts`** кэширует неудачу загрузки CDN намеренно и это
  задокументировано — заблокированный ad-блокером скрипт дёргать снова
  бессмысленно. Не путать с защёлками из пункта 1.
