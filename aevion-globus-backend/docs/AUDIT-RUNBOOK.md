# Аудиты накопленных последствий — что запускать и как читать

Появилось 28.07.2026. Смысл этого файла: **исправление дефекта в коде не
исправляет то, что он уже натворил в базе.** Оба аудита ниже показывают
накопленное, ничего не меняя.

Общие свойства:

- **Только чтение.** Ни `UPDATE`, ни `DELETE`, ни `CREATE` — только `SELECT`.
  Чинить они намеренно не умеют: пересчёт данных на проде — решение владельца,
  а не побочный эффект диагностики.
- Нужен `DATABASE_URL` боевой базы. Скрипт печатает хост, к которому подключился,
  первой строкой — сверьте, прежде чем читать выводы.
- Коды выхода: `0` — чисто, `2` — есть находки, `1` — проверить не удалось.

## 1. Дубли платежей в QGood

```
DATABASE_URL=postgres://... npm run audit:qgood-duplicates
```

**Что проверяет.** До исправления `a94c63b4` у `paymentRef` не было уникального
индекса, а `raisedCents` и `donorCount` росли на каждую запись. Один платёж,
записанный дважды (ретрай вебхука, обновление страницы подтверждения), дважды
поднимал публичную сумму кампании.

**Как читать.**

- `Уникальный индекс … ОТСУТСТВУЕТ` — защиты пока нет, правка ещё не в проде.
- `Дублирующихся платежей нет` — можно ставить индекс, данные править не нужно.
- `НАЙДЕНЫ ДУБЛИ` — два следствия сразу: (а) `CREATE UNIQUE INDEX` упадёт, пока
  дубли не разобраны; (б) суммы кампаний **уже завышены** на указанную величину,
  и это те цифры, которые видят люди на странице.

**Проверен исполнением:** `npm run verify:qgood-audit` — 10 сценариев на
настоящем движке Postgres, включая проверку того, что скрипт не меняет данные.

## 2. Расхождение счётчика участников в QEvents

```
DATABASE_URL=postgres://... npm run audit:qevents-drift
```

**Что проверяет.** Число участников хранится дважды: колонка `attendeeCount` и
строки `QEventRSVP` со статусом `going`. До исправления `c9c5fa94` счётчик росли
безусловно и отдельным запросом вне транзакции, поэтому расхождение накапливалось.

**Как читать.**

- `счётчик больше записей` — событие показывает участников, которых нет.
- `счётчик меньше записей` — обратное; реже, но тоже расхождение.
- `ВЫШЕ ВМЕСТИМОСТИ` — самое неприятное: такое событие **уже пускало людей сверх
  лимита**, потому что вместимость в проде не проверялась вовсе.

Пересчёт — `UPDATE "QEvent" SET "attendeeCount" = <число записей going>`, но
только осознанно и по списку из отчёта.

## Почему это отдельный жанр, а не тест

Тест отвечает на вопрос «правильно ли работает код сейчас». Эти скрипты — на
вопрос «что осталось от того, как он работал раньше». Второй вопрос забывают
задавать: дефект закрыт, тесты зелёные, а неверные числа продолжают показываться
людям. Правило простое: **починил молчащий дефект — спроси, что он успел
накопить, и сделай для этого отдельный аудит.**
