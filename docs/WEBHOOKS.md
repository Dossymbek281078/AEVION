# Вебхуки: что проверено 28.07.2026

Аудит обеих сторон — входящие (нам платят) и исходящие (мы уведомляем). Здесь
только проверенные факты, чтобы следующий заход не выводил их заново.

## Входящие: подделанный запрос отклоняется

| Провайдер | Чем подтверждается подлинность | При неудаче |
|---|---|---|
| LemonSqueezy | HMAC по СЫРОМУ телу | отказ |
| Paybox | `pg_sig` | 401 |
| PayPal | `verify-webhook-signature` через их API | 401 |
| Gumroad | HMAC **только если задан** `GUMROAD_WEBHOOK_SECRET` | см. ниже |

**Gumroad — единственное открытое место.** Секрет на проде не задан, поэтому
подпись не проверяется. Подстраховка стоит с 26.07: код спрашивает у Gumroad API,
существует ли продажа, и отклоняет 401 при определённом `not_found`. При
`unverifiable` (нет `GUMROAD_ACCESS_TOKEN`, сеть, 5xx) — сознательно провижинит,
чтобы настоящий покупатель не терял оплаченное.

Остаточный риск: пока защита опирается на доступность чужого API, в минуты его
недоступности поддельный пинг снова даёт платный тариф. **Закрывается установкой
`GUMROAD_WEBHOOK_SECRET`** — это секрет, задаёт основатель. Признак применения:
`GET /api/gumroad/webhook` вернёт `signed: true`.

## Исходящие: подписаны все пять

| Доставщик | Заголовок подписи |
|---|---|
| `lib/webhookDelivery.ts` | `X-AEVION-Signature` |
| `lib/modules/webhooks.ts` | `X-AEVION-Signature` |
| `lib/qshield/webhooks.ts` | `X-QShield-Signature` |
| `lib/qsignV2/webhooks.ts` | `X-QSign-Signature` |
| `lib/qcoreWebhook.ts` | `X-QCore-Signature` |

**Долг, не дефект:** пять независимых реализаций HMAC с пятью именами заголовка,
при том что в `lib/webhookSig.ts` лежит общий модуль, который НЕ импортирует ни
одна из них. Интегратору приходится поддерживать пять схем проверки вместо одной,
а следующая подсистема легко добавит шестую — или забудет подписать вовсе.

Сведение к одному модулю требует решения основателя: смена имени заголовка ломает
уже подключённых получателей, то есть это внешнее изменение, а не рефакторинг.

## Требования к новому доставщику

1. Подписывать отправку HMAC по СЫРОМУ телу, а не по пересобранному JSON.
2. Использовать `lib/webhookSig.ts`, а не писать шестую реализацию.
3. Секрет получателя брать из его записи, а не общий на всех.

## Ложная тревога, о которой стоит знать

Первая версия обхода пометила `services/qcoreai/userWebhooks.ts` как
«не подписывает»: ни HMAC, ни заголовка. На деле это ХРАНИЛИЩЕ — только
`SELECT`/`INSERT`, отправки в нём нет вовсе, доставляет `lib/qcoreWebhook.ts`, и
он подписывает.

Признак «в файле нет HMAC» не различает доставщика и хранилище. Проверяя такое,
сначала убедитесь, что файл вообще делает `fetch(` — иначе получите требование
подписи к таблице.
