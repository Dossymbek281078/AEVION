## Зачем

Механика Higgsfield, замеренная через их живой биллинг 2026-07-26 (не по памяти — фактический ответ их pricing-API): одна покупка не выдаёт один товар, она *радиирует* по каталогу — разной глубиной, на ограниченный срок, и список того, что откроется, показан **до** оплаты. У них это «365-DAY UNLIMITED» на 7 моделей + «7-Day Unlimited» на 2-3 горячие + лестница объёма 39→42→44%.

У AEVION 43 модуля в прайсе и другая экономика: нет амортизированного GPU-парка, есть реальный per-token/per-render COGS. Поэтому веер здесь — **скидка на соседние модули**, а не «unlimited».

## Механика

```
ring 1  прямой комплемент   −30% → до −45%   один кластер (BUNDLES + 12 явных) или ≥2 общих тега
ring 2  тот же домен        −15% → до −30%   ≥1 общий тег в projects.ts
ring 3  остальная планета     0%             прайс без скидки
```

Уровень веера = число купленных платных модулей (1..5), каждый добавляет +5 п.п. кольцам 1-2. Окно — 14 дней от покупки, продлевается новой покупкой. Скидка фиксируется на оплаченный период.

**Четыре потолка, все обязательные:** потолок кольца → общий 50% (тот же `MAX_PROMO_DISCOUNT_RATIO`, что у промокодов — намеренно один number, два независимых разъехались бы) → 30% для 15 модулей с переменным COGS (оба гейта `QCOREAI_*_QUOTA` до сих пор dormant, per-модульный COGS не измерен) → совместный «веер + промо ≤ 50%», без которого «промо −50% + веер −45%» давало заказ дешевле нуля.

**ring 3 = 0% по замеру, а не по вкусу:** при уровне 1 в ring3 падало 27 модулей из 31, и «−10% на всё» превращало прайс в фикцию. Замер это показал, тесты — нет.

## Что появилось

**Бэкенд**
- `data/fanDiscounts.ts` — движок (кольца, лестница, потолки, окно, витрина). Единственная точка, где веер попадает в деньги, — `buildQuoteWithFan()`; и `/quote`, и чекаут зовут её, поэтому «смета == списание» держится по построению.
- `POST /api/pricing/fan`, `GET /api/pricing/fan/preview`, `GET /api/pricing/fan/me`.
- `GET /api/pricing/checkout/discount-integrity?days=N` — сколько скидок пообещали и не применили. Postgres (`discount_integrity_log`) по паттерну `lib/paywallDenyLog.ts`, при недоступной базе — счётчики в памяти с честным `source: "memory"` + `bootedAt`.
- `scripts/ls-variant-price-drift.js` — канарейка инварианта «цена LS-варианта == цена в `data/pricing.ts`», который держался на комментарии.

**Фронтенд**
- `FanDiscountPanel` на `/pricing`: авторизованному покупателю веер приходит с сервера (`/fan/me`, оба стора), гостю остаётся витрина «что будет, если купить». Предложения кликабельны и ведут на `/pricing?module=…`. Размечено четырьмя событиями (`fan_view`, `fan_owned_pick`, `fan_offer_click`, `fan_terms_open`) — иначе окно 14 дней и глубину нечем проверить; веерная строка в `ModulePricingChip` (28 витрин); веерное предложение в стене 402; «цена по запросу» для 8 модулей без прайса → лид с названием модуля.
- Paywall переведён в светлую схему. Акценты пересчитаны: старые давали на белом 1.92–4.23:1 при норме AA 4.5:1, новые 4.76–7.10:1.
- Копирайт — `lib/pricingI18n/sections/fan.ts` (ru/en), не хардкод.

## Требует руки основателя

- **Мерж.**
- **`LEMON_SQUEEZY_ALLOW_CUSTOM_PRICE=1` на Railway** (или offer-коды в LS/Gumroad) — иначе скидки остаются реальными только на PayPal/PayBox, и API про это честно говорит.

- Веер в DevHub-флоу — зона `frontend-qcore` по `AEVION_COORDINATION.md`.
- `tests/devhub-integrations.test.ts` флакует под параллельной нагрузкой (счёт падений 4→3→1→0 при неизменном коде, в изоляции 191/191 дважды). Гигиена моков и env исключена чтением; детерминированного воспроизведения нет. Чужая зона — оставлено владельцу как факт, не как догадка.
