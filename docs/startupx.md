# StartupX — биржа стартапов

Модуль `startup-exchange` (код `STARTUPX`) в монорепо `aevion-core`.
Фронт — `frontend/src/app/startup-exchange/`, бэкенд — `aevion-globus-backend/src/routes/startupExchange.ts`
и `src/lib/startupx/`.

Рыночный контекст и мировые аналоги — `startupx-market.md`.

---

## 1. Что продаётся на трёх уровнях

| Уровень | Что есть у основателя | Что обсуждается | Типичный чек инвестора |
|---|---|---|---|
| `idea` | ничего не построено | доля за вложение в разработку | $5K – $50K |
| `mvp` | работающий прототип | доля за вложение в доработку; кто доводит — часть сделки | $25K – $250K |
| `product` | работающее приложение | выкуп целиком или выкуп доли | $50K – $2M |

Уровень — главная ось. Старая колонка `stage` осталась (на ней CHECK-констрейнт и старые
строки) и всегда пишется из уровня, поэтому разойтись они не могут.

**Что заявка обязана содержать, чтобы быть опубликованной:** тип сделки и пару чисел под него
(`askUsd` + `equityOfferedPct`, либо `askingPriceUsd`, либо `stakeForSalePct` + `stakePriceUsd`).
Для `mvp` и `product` — ещё и рабочая ссылка. Без этого API отвечает 400 со списком полей:
заявка без условий — это объявление «напишите мне», ради замены которого биржа и существует.

## 2. API

| Метод | Путь | Кто может | Зачем |
|---|---|---|---|
| `GET` | `/api/startupx/tiers` | все | правила уровней, отрасли, источники, дисклеймер — UI рисует их отсюда, а не из своей копии |
| `POST` | `/api/startupx/assess` | все | бесплатный разбор черновика; **ничего не сохраняет**, условия сделки не обязательны |
| `GET` | `/api/startupx/ideas` | все | лента; фильтры `tier`, `sector`, `minScore`, сортировка `recent`/`score` |
| `GET` | `/api/startupx/ideas/:id` | все | одна заявка (только `visibility='public'`) |
| `POST` | `/api/startupx/ideas` | все | публикация; в ответе **один раз** отдаётся `manageToken` |
| `PATCH` | `/api/startupx/ideas/:id?token=` | основатель | правка условий, цифр и ссылок; разбор пересчитывается |
| `DELETE` | `/api/startupx/ideas/:id?token=` | основатель | снятие с публикации (`visibility='withdrawn'`, строка сохраняется) |
| `POST` | `/api/startupx/ideas/:id/interest` | все | отклик инвестора с условиями (чек, доля, тип сделки) |
| `GET` | `/api/startupx/ideas/:id/offers?token=` | основатель | входящие предложения |
| `POST` | `/api/startupx/ideas/:id/reassess` | все | пересчёт по текущим правилам (когда двигается `ASSESSMENT_VERSION`) |

### Токен основателя

Выдаётся один раз при публикации; в базе хранится только SHA-256. Сравнение — `timingSafeHexEq`.
Восстановить нельзя даже нам, и интерфейс говорит это в момент выдачи.

Неверный токен и заявка, опубликованная до появления токенов, дают одинаковый **401**: разные
ответы помогали бы только тому, кто подбирает.

Страница `/startup-exchange/<id>/offers?token=…` закрыта `noindex, nofollow, nocache` и
`referrer: no-referrer` — иначе секрет из URL уехал бы в поисковый индекс или в `Referer`
при клике на почту инвестора.

## 3. Разбор

Детерминированный, без обращения к языковой модели (`src/lib/startupx/assess.ts`). Ноль
стоимости за заявку, одинаковые правила для всех — поэтому два проекта сравнимы.

Пять факторов с разными весами по уровням: ясность заявки, рынок, защитимость,
доказательства, условия сделки. Каждый сообщает **основание**: `company-evidence` (по данным
заявки) / `sector-prior` (по отрасли) / `text-only` (по тексту), и `evidenceCoverage`
показывает, какая доля балла стоит на раскрытых цифрах.

Что зашито в контракт, а не в вёрстку:
- `disclaimer` — «не гарантирует ни успеха, ни неудачи» — часть ответа;
- `blindSpots` — команда, юр. чистота, качество кода, достоверность цифр — тоже;
- обещание гарантированного дохода — красный флаг высокой важности (это и неправда, и в
  большинстве юрисдикций признак незаконного предложения инвестиций).

**Цена.** Мы не оцениваем проект. Мы показываем диапазон, в котором рынок закрывает сделки
такой формы, и во сколько раз запрос из него выходит. Для `product` с выручкой — мультипликатор
1.3–5× с интерполяцией по log10 (брекеты давали обрыв на границе $100K); без выручки — полоса
по уровню. Источники — `MARKET_SOURCES` в `valuation.ts`, они же на экране.

**Отрасль.** Указанная основателем побеждает. Иначе — голосование по ключевым словам
(двуязычное, по заголовку и описанию); нужно ≥2 разных совпадения и отрыв от второй отрасли,
иначе честный `fallback` с явной пометкой «цифры рынка общие».

**Против накрутки.** Подсказки ясности засчитываются только из объясняющих предложений: короче
четырёх слов — не считается, перечисление через запятую — тоже. Набитый ключевыми словами текст
даёт 42 вместо 88.

## 4. Границы, которые нельзя переходить

- **Текст заявки заморожен после публикации.** SHA-256 покрывает название, описание и уровень
  на дату подачи. `PATCH` меняет только условия, цифры и ссылки. Штамп авторства, молча
  следующий за правками, не стоит ничего.
- **Цифры не проверяются.** Везде написано «со слов основателя». Верификация выручки через
  Stripe (как у TrustMRR) — следующий шаг, и до него нельзя говорить «проверено».
- **`ASSESSMENT_VERSION` двигается при любом изменении правил.** Балл принадлежит правилам,
  которые его сделали; иначе лента сравнивает несравнимое.
- **Миграция только добавляет колонки** (`ADD COLUMN IF NOT EXISTS`) и разово проставляет
  `tier` по старому `stage`. Тест сверяет SQL-бэкфилл с TS-маппингом, чтобы они не разошлись.

## 5. Проверки

```
npx vitest run tests/startupxListings.test.ts     # 30 тестов
BASE=http://127.0.0.1:4001 node scripts/startupx-smoke.js   # 49 проверок
node scripts/startupx-seed.js                     # сухой прогон первых заявок
```

Смоук входит в `all-smokes` и гоняется в daily-smoke против эфемерного Postgres. Он проверяет
способность, а не коды ответов: отказ публиковать без условий, отказ принять «готовый продукт»
без ссылки, пересчёт пост-оценки, чтение кириллицы, чужой токен → 401, и уборку за собой.
