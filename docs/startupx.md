# StartupX — биржа стартапов

Модуль `startup-exchange` (код `STARTUPX`) в монорепо `aevion-core`.
Фронт — `frontend/src/app/startup-exchange/`, бэкенд — `aevion-globus-backend/src/routes/startupExchange.ts`
и `src/lib/startupx/`.

Рыночный контекст и мировые аналоги — `startupx-market.md`.

---

## 1. Что продаётся на трёх уровнях

| Уровень | Что есть у основателя | Что обсуждается | Типичный чек инвестора |
|---|---|---|---|
| `idea` | ничего не построено | доля за вложение в разработку | $5K – $50K |
| `mvp` | работающий прототип | доля за вложение в доработку; кто доводит — часть сделки | $25K – $250K |
| `product` | работающее приложение | выкуп целиком или выкуп доли | $50K – $2M |

Уровень — главная ось. Старая колонка `stage` осталась (на ней CHECK-констрейнт и старые
строки) и всегда пишется из уровня, поэтому разойтись они не могут.

**Что заявка обязана содержать, чтобы быть опубликованной:** тип сделки и пару чисел под него
(`askUsd` + `equityOfferedPct`, либо `askingPriceUsd`, либо `stakeForSalePct` + `stakePriceUsd`).
Для `mvp` и `product` — ещё и рабочая ссылка. Без этого API отвечает 400 со списком полей:
заявка без условий — это объявление «напишите мне», ради замены которого биржа и существует.

## 2. API

| Метод | Путь | Кто может | Зачем |
|---|---|---|---|
| `GET` | `/api/startupx/tiers` | все | правила уровней, отрасли, источники, дисклеймер — UI рисует их отсюда, а не из своей копии |
| `POST` | `/api/startupx/assess` | все | бесплатный разбор черновика; **ничего не сохраняет**, условия сделки не обязательны |
| `GET` | `/api/startupx/ideas` | все | лента; фильтры `tier`, `sector`, `minScore`, сортировка `recent`/`score` |
| `GET` | `/api/startupx/ideas/:id` | все | одна заявка (только `visibility='public'`) |
| `POST` | `/api/startupx/ideas` | все | публикация; в ответе **один раз** отдаётся `manageToken` |
| `PATCH` | `/api/startupx/ideas/:id?token=` | основатель | правка условий, цифр и ссылок; разбор пересчитывается. `restore: true` возвращает снятую заявку в ленту |
| `DELETE` | `/api/startupx/ideas/:id?token=` | основатель | снятие с публикации (`visibility='withdrawn'`, строка сохраняется) |
| `POST` | `/api/startupx/ideas/:id/interest` | все | отклик инвестора с условиями (чек, доля, тип сделки) |
| `GET` | `/api/startupx/ideas/:id/offers?token=` | основатель | входящие предложения |
| `POST` | `/api/startupx/ideas/:id/reassess` | все | пересчёт по текущим правилам (когда двигается `ASSESSMENT_VERSION`) |
| `GET` | `/api/startupx/stats` | все | счётчики ленты + `assessmentVersion` и `staleAssessments` |
| `GET` | `/api/startupx/health` | все | `dbReady` — используется ли Postgres или включился in-memory фолбэк; `publishPerDay` / `publishRemaining` — суточный потолок публикаций и остаток для этого адреса; `clientIp` — как модуль видит адрес звонящего (проверка после деплоя, см. §4) |
| `GET` | `/api/startupx/status` | все | карточка модуля для витрины MVP |

### Токен основателя

Выдаётся один раз при публикации; в базе хранится только SHA-256. Сравнение — `timingSafeHexEq`.
Восстановить нельзя даже нам, и интерфейс говорит это в момент выдачи.

Неверный токен и заявка, опубликованная до появления токенов, дают одинаковый **401**: разные
ответы помогали бы только тому, кто подбирает.

Страница `/startup-exchange/<id>/offers?token=…` закрыта `noindex, nofollow, nocache` и
`referrer: no-referrer` — иначе секрет из URL уехал бы в поисковый индекс или в `Referer`
при клике на почту инвестора.

## 3. Разбор

Детерминированный, без обращения к языковой модели (`src/lib/startupx/assess.ts`). Ноль
стоимости за заявку, одинаковые правила для всех — поэтому два проекта сравнимы.

Пять факторов с разными весами по уровням: ясность заявки, рынок, защитимость,
доказательства, условия сделки. Каждый сообщает **основание**: `company-evidence` (по данным
заявки) / `sector-prior` (по отрасли) / `text-only` (по тексту), и `evidenceCoverage`
показывает, какая доля балла стоит на раскрытых цифрах.

Что зашито в контракт, а не в вёрстку:
- `disclaimer` — «не гарантирует ни успеха, ни неудачи» — часть ответа;
- `blindSpots` — команда, юр. чистота, качество кода, достоверность цифр — тоже;
- обещание гарантированного дохода — красный флаг высокой важности (это и неправда, и в
  большинстве юрисдикций признак незаконного предложения инвестиций).

**Цена.** Мы не оцениваем проект. Мы показываем диапазон, в котором рынок закрывает сделки
такой формы, и во сколько раз запрос из него выходит. Для `product` с выручкой — мультипликатор
1.3–5× с интерполяцией по log10 (брекеты давали обрыв на границе $100K); без выручки — полоса
по уровню. Источники — `MARKET_SOURCES` в `valuation.ts`, они же на экране.

**Отрасль.** Указанная основателем побеждает. Иначе — голосование по ключевым словам
(двуязычное, по заголовку и описанию); нужно ≥2 разных совпадения и отрыв от второй отрасли,
иначе честный `fallback` с явной пометкой «цифры рынка общие».

**Против накрутки.** Подсказки ясности засчитываются только из объясняющих предложений: короче
четырёх слов — не считается, перечисление через запятую — тоже. Набитый ключевыми словами текст
даёт 42 вместо 88.

## 4. Границы, которые нельзя переходить

- **Текст заявки заморожен после публикации.** SHA-256 покрывает название, описание и уровень
  на дату подачи. `PATCH` меняет только условия, цифры и ссылки. Штамп авторства, молча
  следующий за правками, не стоит ничего.
- **Цифры не проверяются.** Везде написано «со слов основателя». Верификация выручки через
  Stripe (как у TrustMRR) — следующий шаг, и до него нельзя говорить «проверено». Единственное,
  что делается без верификации, — сверка чисел между собой: цена ниже половины заявленной выручки
  или выше 6× от неё поднимает флаг, иначе выдуманная выручка читалась бы как выгодная сделка.
- **Отрасль резолвится только через `safeResolveSector`.** Общий справочник индексируется
  строкой, а любой объект отвечает на `constructor`, `toString`, `valueOf`, `__proto__` —
  замерено: заявка с `sector=constructor` давала label `undefined`, TAM `undefined` и балл
  рынка 0 при полностью «успешном» ответе.
- **`ASSESSMENT_VERSION` двигается при любом изменении правил.** Балл принадлежит правилам,
  которые его сделали; иначе лента сравнивает несравнимое. Это стережёт тест с отпечатком
  правил (проверено: сдвиг веса на 0.04 красит его), а `/stats` показывает `assessmentVersion`
  и `staleAssessments` — сколько строк ждут `/reassess`.
- **Суточный потолок публикаций считает опубликованное, а не попытки.** Минутный лимит (5 в
  минуту) защищает сервер, но не ленту: 300 заявок в час — это затопленная витрина. Потолок —
  `STARTUPX_PUBLISH_PER_DAY`, по умолчанию 5 на адрес в сутки; списывается только тогда, когда
  заявка действительно появилась в ленте, иначе основатель, пять раз промахнувшийся мимо
  обязательного поля, терял бы право подать заявку на сутки. Ворота стоят **перед** минутным
  лимитом: когда исчерпаны оба, человеку надо сказать «сегодня всё» (`daily_publish_limit`), а
  не «подождите минуту» — минута ему не поможет. Чего потолок не делает: `X-Forwarded-For`
  приходит от клиента и подделывается, поэтому упорный флудер обойдёт счётчик сменой адреса —
  от этого защищает очередь модерации и жалобы, а не лимит.
- **Письмо об отклике не выдаёт того, чего у нас нет.** Основателю уходит уведомление «пришёл
  отклик» с условиями сделки — но без ссылки на кабинет (токен хранится только как SHA-256,
  восстановить его нельзя) и без адреса и текста инвестора: почта основателя введена в форме и
  не подтверждена, а чужой контакт не отправляют по непроверенному адресу. Без SMTP в окружении
  письмо просто не уходит, и это не ошибка — отклик не должен падать из-за почты.
  Транспорт — общий `src/lib/mailTransport.ts` (у `planningEmail.ts` и `build/email.ts` свои
  копии, новые отправители берут отсюда).
- **База, которая отказала, отвечает 503 — не «не найдено» и не тихой записью в память.**
  Раньше любой сбой запроса проваливался в in-memory ветку: чтение говорило основателю «заявка
  не найдена», хотя строка цела, а публикация уходила в оперативку и исчезала на ближайшем
  рестарте. Память — законный режим только там, где базы не предполагалось (`DATABASE_URL` не
  задан). Замерено 27.07 на живом Postgres 18: при исчерпании подключений `GET /ideas/:id`
  отдавал 404 на существующую заявку.
- **Готовность базы не решается один раз при старте.** `ensureStartupExchangeTables` латчится
  только на успехе; после неудачи роутер пробует снова на каждом запросе, но не чаще раза в
  10 секунд. Замерено там же: первое подключение при старте отвалилось по таймауту, и модуль
  оставался в памяти при полностью живой базе — в проде это заявки, исчезающие на рестарте.
- **Экранирование поиска проверяется только на Postgres.** In-memory ветка ищет через
  `includes` и переживает любые ошибки экранирования; на настоящей базе запрос «5%» молча
  отдавал пустую ленту. Две причины сразу: `` `\${m}` `` в шаблонной строке — это литерал
  «${m}», а `ESCAPE '\'` — это SQL `ESCAPE ''`, то есть отсутствие экранирования.
- **После деплоя проверить, что адрес клиента доезжает.** Страница ходит в API через rewrite
  на фронте, то есть до бэкенда запрос доезжает от сервера Vercel. Если адрес клиента при этом
  теряется, все основатели становятся одним адресом, и суточный потолок превращается из защиты
  ленты в «пять заявок в сутки на всю биржу». Проверка на минуту: открыть
  `/api/startupx/health` с двух разных устройств и сравнить `clientIp`. Разные — всё в порядке.
  Одинаковые — снять потолок (`STARTUPX_PUBLISH_PER_DAY` большим числом) и вернуть его, когда
  адрес будет доезжать. Локально это не проверяется: там и клиент, и прокси — петля.
- **Миграция только добавляет колонки** (`ADD COLUMN IF NOT EXISTS`) и разово проставляет
  `tier` по старому `stage`. Тест сверяет SQL-бэкфилл с TS-маппингом, чтобы они не разошлись.

## 5. Проверки

```
npx vitest run tests/startupxListings.test.ts     # 36 тестов
npx vitest run tests/inMemoryWindow.test.ts       # 5 тестов общего лимитера (peek/уборка ключей)
BASE=http://127.0.0.1:4001 node scripts/startupx-smoke.js   # 81 проверка
node scripts/startupx-seed.js                     # сухой прогон первых заявок
npx ts-node -T scripts/startupx-terms-lab.ts      # балл и полоса цены по шаблону первых заявок
BASE=http://127.0.0.1:4001 node scripts/startupx-hostile.js  # мусор в каждое поле каждой ручки
```

Смоук падает, если `DATABASE_URL` задан, а `dbReady` вернулся `false`: молчаливый откат на
in-memory store удобен для превью-деплоев, но в среде с базой он означает сломанную миграцию
и данные, которые исчезнут при рестарте.

Обход мусором (`startupx-hostile.js`) шлёт 123 запроса: ключи прототипа в каждое место, где
значение ищут по строке, массивы и объекты вместо строк, `NaN`/`Infinity`/`1e309` вместо
чисел, строку в 100 000 знаков, метасимволы `LIKE`, XML-разрыв в то, из чего собирается RSS,
перевод строки в адресе почты, чужие токены и битые тела. Находкой считается 500, оборванное
соединение, `undefined`/`NaN` внутри 200-го ответа или сырой `<script>` в канале — то есть
«не упало, но тихо соврало», а не отказ как таковой. Первый прогон 27.07 дал два 500 на битом
теле (обе — одна причина, см. ниже), после правки — ноль находок на 123 запросах.

Смоук входит в `all-smokes` и гоняется в daily-smoke против эфемерного Postgres. Он проверяет
способность, а не коды ответов: отказ публиковать без условий, отказ принять «готовый продукт»
без ссылки, пересчёт пост-оценки, чтение кириллицы, чужой токен → 401, и уборку за собой.

## 6. Что осталось на потом

- **Проверка выручки.** Сейчас везде написано «со слов основателя». Подключение Stripe/LemonSqueezy
  (как у TrustMRR) — единственный способ заменить эту формулировку на «проверено».
- **Миграция на настоящем Postgres.** Локально пароля к серверу нет; в CI daily-smoke база есть,
  и страж `dbReady` сделает поломку громкой — но прогнать её глазами до мержа не удалось.
