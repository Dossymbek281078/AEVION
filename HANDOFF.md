## ✅ Серверный Chessy-кошелёк (PR #671, на проде, живой факт подтверждён)

Клиентский Chessy (60+ мест `addChessy`/`spendChessy` в page.tsx) не менялся и остаётся как есть — вне scope. Добавлен ОТДЕЛЬНЫЙ, параллельный, серверно-доверенный кошелёк (`CyberWallet` в Postgres, `cyberchessMatchStore.ts`), питается ТОЛЬКО от `finalizeMatch()` (результат уже проверен сервером через #622 — не клиентская заявка): победа +10, ничья +3, участие +1. `GET /api/cyberchess/matchmaking/wallet?userId=X` и `/wallet/leaderboard?limit=N`.

**Зачем:** без этого публичный лидерборд/командные ставки (следующие шаги дизайна экономики) были бы тривиально читерски — Chessy сейчас живёт в localStorage, «облачная синхронизация» просто сохраняет что клиент прислал, без проверки.

**Живой прод-тест:** реальный матч через matchmaking до мата (Fool's Mate) → победитель `balance:10`, проигравший `balance:1`, `/wallet/leaderboard` вернул обоих в верном порядке. Локальный сквозной тест не прошёл из-за лимита подключений shared-БД (та же проблема что у #660) — SQL-логика была провалидирована напрямую через psql до пуша, прод подтвердил всё end-to-end.

**Следующий слой (не начат):** пока это чистый backend — нигде в UI игрок не видит свой Chessy-кошелёк/лидерборд. Дальше — фронтенд-страница лидерборда, затем сезонный трек/скины поверх этого фундамента (см. документ экономики выше по коду).

## ✅ Rush Survival больше не ловит время из Rush-Timed (PR #657, на проде)

Совпадает дословно с жалобой основателя «3 и 5 минут не работали, или рандомное время». `rushDuration` (пресет Timed-режима) хранится в localStorage и протекал в Survival-сессию через путь решения одноходовых пазлов (самый частый случай) — единственное место, забытое при добавлении Survival в PR #613. Часы 10-минутного safety-net резко обрезались до 3/5 мин сразу после первого решённого пазла. Однострочный фикс по образцу уже рабочего соседнего пути (multi-move пазлы).

## ✅ Пул пазлов 10.8k → 500k (PR #636, на проде)

Последний известный разрыв с lichess/chess.com по масштабу (не по глубине — теория/коуч уже сильнее среднего). `ChessPuzzle` в Postgres засеяна из CC0 `lichess_db_puzzle.csv` (database.lichess.org, 6.06M строк дамп, рейтинг-фильтр 400–2800) через уже существовавший `scripts/seed-puzzles.mjs` → `POST /api/puzzles/seed` (гейт `X-Puzzle-Seed-Key`/`PUZZLE_SEED_KEY`, переменная создана на Railway 2026-07-16).

**Найдена и закрыта операционная дыра:** `cyberchessPuzzles.ts` кэширует пул через `ensureLoaded()`/`loadPromise` **на весь lifetime процесса** — уже запущенный backend не видит новые строки в БД до своего следующего рестарта. Добавлен `POST /api/cyberchess-puzzles/reload` (PR #636, admin-gated `X-Admin-Key`/`CYBERCHESS_ADMIN_KEY`, тот же паттерн что `cyberchessDaily.ts /reset`) — форсирует re-query без полного редеплоя. На этот раз не понадобился: естественный редеплой (в этот backend постоянно что-то мержится из параллельных сессий) подхватил 500k раньше, чем понадобился ключ.

**Живой прод-факт:** `https://api.aevion.app/api/cyberchess-puzzles?limit=1` → `"poolSize":500000`. Дамп (302МБ .zst → 1.1ГБ CSV) лежал в scratchpad, зачищен не был намеренно (может пригодиться на будущее для re-seed с другими фильтрами — see [[project_cyberchess_server_move_validation_2026_07_16]]).

**Инфраструктурная грабля (важно на будущее):** Node 24 нативный `zlib.zstdDecompressSync`/`createZstdDecompress` падает на многофреймовых дампах Lichess (`Unknown frame descriptor` / `ZSTD_error_prefix_unknown`) — нужен внешний `zstd.exe` бинарник (см. [[project_cyberchess_opening_tree]], та же грабля что и для дерева дебютов).

## ✅ PR #622 (смёржен, на проде) — серверная валидация ходов/результата matchmaking

Последний повторяющийся 🔴 из аудитов (#499 → ux_lag_fix → theory_depth): `/match/:id/move` проверял только форму UCI регуляркой (без легальности/очерёдности хода), `/match/:id/end` брал `{result}` НАПРЯМУЮ из тела запроса — любой аутентифицированный участник мог `curl /end {result:"white"}` на нетронутой доске и получить Glicko-2 победу.

**Что сделано** (`aevion-globus-backend/src/routes/cyberchessMatchmaking.ts`):
- `Match` теперь несёт серверный `chess: Chess` (chess.js добавлен в backend, `^1.4.0`, как во frontend). `/move` проверяет очерёдность хода (нельзя ходить не в свой ход/чужой фигурой) + полную легальность (связки/шах/рокировка/взятие на проходе/превращение) через `chess.move()`.
- Легальный ход, сам заканчивающий партию (мат/пат/ничья), **сервер финализирует сам** — не ждёт `/end` от клиента.
- `/end`: если доска объективно завершена — результат берётся с доски, что бы ни прислал клиент. Если доска НЕ завершена — участник может заявить только своё поражение или ничью; самоприсуждение победы принимается ТОЛЬКО если серверная арифметика часов (из таймстампов ходов + timeControl, без отдельного таймер-процесса) показывает, что флаг соперника реально упал. Повторный `/end` идемпотентен — отдаёт настоящий результат, не заявку второго вызова.
- Побочный баг найден и исправлен: `frontend/src/app/cyberchess/page.tsx` (~1872) слал uci только как `{from}{to}` без буквы превращения — реальное превращение молча приходило к сопернику как ферзь (`exec`'s `pr||"q"`) и было бы отклонено новой серверной проверкой. Теперь буква превращения берётся из SAN последнего хода.

**Живой тест (curl, localhost:4055, без DB)** — все сценарии подтверждены: нелегальный ход отклонён, чужая фигура/чужой ход отклонены, самоприсуждение победы на свежей доске отклонено, честная капитуляция принята, повторный `/end` отдаёт истинный результат, Fool's Mate авто-финализируется без `/end`, мгновенная поддельная заявка «таймаут» отклонена, честная заявка после реального истечения 60с часов принята.

## ✅ Timeout-концовки теперь тоже получают богатый оверлей (PR #655, на проде)

Живой клик-тест #643 вскрыл реальный баг (не тестовый артефакт — перепроверено чтением всех мест окончания партии в файле): оба колбэка часов (`pT`/`aT`, `page.tsx:2304-2305`) вызывали только `sOver(...)`, без `sOn(false)` — единственные из 7+ мест окончания партии (мат/капитуляция/варианты/P2P), где парный сеттер отсутствовал. Из-за этого `on` оставался `true` навсегда после таймаута, а богатый `showGameOver`-оверлей (accuracy/blunder-map/AI-разбор из #643) требует `!on` — значит РЕАЛЬНЫЕ игроки никогда не видели полный разбор после поражения/победы по времени, только урезанную карточку. Однострочный фикс, паттерн скопирован с уже работающих мест. `Resign` через `window.confirm()` — НЕ баг, это устоявшийся паттерн (12 мест в файле), проверил и отменил свою же более раннюю ошибочную гипотезу.
