# QSpace — 3D-модельер помещений

Страница `/qspace`. Модуль целиком в браузере: бэкенд ему не нужен, всё
считается на клиенте (three.js). Заведён 07.09.2026 по задаче основателя
«2D-план из автокада, PDF или JPEG → 3D-модель с послойным ракурсом».

## Из чего состоит

| Файл | За что отвечает |
|---|---|
| `planModel.ts` | модель плана (стены, проёмы), генераторы электрики, труб, света |
| `dxf.ts` | разбор DXF (LINE, LWPOLYLINE, единицы из `$INSUNITS`) |
| `pdf.ts` | разбор ВЕКТОРНОГО PDF без внешних библиотек (Flate средствами платформы) |
| `raster.ts` | стены на растровом плане обходом пикселей |
| `RasterReview.tsx` | экран ручной правки распознанного — обязательный шаг |
| `openings.ts` | установка окон и дверей нажатием на стену |
| `rooms.ts` | выделение помещений заливкой, площадь и периметр |
| `roomSpec.ts` | спецификация по комнатам + текст для подрядчика |
| `estimate.ts` | спецификация по всему плану |
| `materials.ts` | каталог отделки, процедурные текстуры |
| `furniture.ts` | каталог мебели (40 позиций) с реальными габаритами |
| `clearance.ts` | проверка расстановки: пересечения, дверь, за планом, потолок |
| `passage.ts` | проходимость: не отрезала ли мебель часть комнаты от двери |
| `heating.ts` + `HeatingPanel.tsx` | тёплый пол: метры трубы, шаг, контуры, мощность |
| `ventilation.ts` + `VentilationPanel.tsx` | воздухообмен и влажность по назначению комнат |
| `floorPlanSvg.ts` | чертёж сверху в SVG для печати |
| `wallStructure.ts` | состав конструкций и чистовая высота |
| `project.ts` | сохранение проекта: браузер + файл `.qspace.json` |
| `_client.tsx` | сцена three.js и весь интерфейс |

## Правила, которые тут держатся (не ломать)

1. **Масштаб у PDF и картинки СПРАШИВАЕТСЯ, а не угадывается.** Угаданный
   масштаб даёт правдоподобно неверную модель — худший класс дефектов.
2. **По распознанной картинке модель не строится молча.** Только через экран
   правки и подтверждение человеком.
3. **Проёмы из чертежа не распознаются** и распознаваться не будут: их рисуют
   блоками и разрывами линий. Их ставит человек.
4. **Отказ показывается отказом.** «Мимо стены», «похоже, это скан», «стена
   0.80 м — дверь не встанет», «браузер не даёт сохранять». Молчание тут
   читается как «не сработало».
5. **Разводка и толщины — черновик по практике**, не проектная документация.
   Это написано на странице, и сторож следит, чтобы формулировка не исчезла.
6. **Числа в описании модуля обязаны совпадать с кодом.** Сторож
   `catalogClaimsMatchCode.test.ts` сверяет их и краснеет, если возможность
   появилась, а описание молчит. Проза стареет молча — за двое суток разошлась
   трижды.

7. **Признак у сторожа возможностей — ФРАЗА, а не слово.** Трижды за одно
   окно сторож был зелёным по чужому слову в том же описании («проход»
   совпал с «проходит экран правки», «чертёж» — с «проёмы из чертежа»).
   И никаких `\w`/`` с кириллицей: в JS они её не покрывают, шаблон
   молча мёртв — против этого стоит `noCyrillicWordClass.test.ts`.
